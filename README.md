# Lean 4: экспериментальный аудит доказательств

## Запуск на GitHub без локальной установки

1. Создайте новый репозиторий на GitHub.
2. Загрузите **содержимое этой папки** в корень репозитория, включая скрытую папку `.github`.
3. Откройте вкладку **Actions** → **Lean 4 proof audit** → **Run workflow** → **Run workflow**.
4. Дождитесь завершения задания `audit`.
5. Откройте страницу запуска и скачайте архив **lean4-audit-results** в разделе **Artifacts**.
6. Отправьте `results.json` и, если возможно, `.log` файлы для внесения фактических результатов в статью.

Workflow также запускается при изменении файлов скрипта, toolchain или самого workflow. Версия Lean закреплена в `lean-toolchain`.

## Локальный запуск

После установки Lean 4 и Python 3 выполните `python run_audit.py` (Windows) или `python3 run_audit.py` (Linux/macOS).

## Сценарии

| Случай | Ожидаемый результат |
|---|---|
| 01_valid | ACCEPT: корректное доказательство `True` |
| 02_sorry | REJECT: зависимость от `sorryAx` |
| 03_custom_axiom | REJECT: зависимость от `injected` |
| 04_statement_substitution | REJECT: изменение формулировки |
| 05_artifact_modified | REJECT: изменение SHA-256 |
| 06_invalid_syntax | REJECT: ошибка Lean |

`03_custom_axiom` использует **доверенную тестовую заготовку**, объявляющую искусственную аксиому; в реальной системе агент не должен иметь права редактировать prelude.

## Ограничения

Это минимальный демонстратор, а не полностью изолированная система аудита: здесь нет песочницы, подписанных журналов, полноценного lockfile библиотек и защиты от исполнения произвольных команд через недоверенный Lean-код. В частности, код Lean должен запускаться только в изолированной среде. Проверка неизменности формулировки в этом прототипе сравнивает строки, а не канонические синтаксические деревья. Данные эксперимента можно считать фактическими только после успешного запуска на машине с Lean.
